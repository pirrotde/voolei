## Project Overview

"Vôlei dos amigos 🏐" - A volleyball team management app for organizing casual matches with automatic team balancing. Built with TanStack Start (SSR React framework), deployed to Cloudflare Workers, using Bun as the package manager.

The app manages player registration, queuing, automatic team formation (4 players per team, up to 2 women per team), score tracking, and match history.

## Architecture

### Entry Points

- **src/server.ts**: Cloudflare Workers entry point that wraps TanStack Start's server with custom error handling. This is the main entry specified in wrangler.jsonc:6
- **src/start.ts**: TanStack Start configuration with error middleware
- **src/router.tsx**: Router factory that creates the TanStack Router instance with QueryClient context

### Error Handling

The app has a robust error handling system:

1. **src/lib/error-capture.ts**: Captures unhandled errors/rejections globally, stores them temporarily (5s TTL)
2. **src/lib/error-page.ts**: Renders a branded error page as fallback
3. **src/server.ts**: Wraps the TanStack Start handler to catch catastrophic SSR errors that h3 swallows into 500 responses with `{"unhandled":true,"message":"HTTPError"}`
4. **src/start.ts**: Middleware that catches errors during request handling and returns branded error pages
5. **src/routes/__root.tsx**: Provides ErrorComponent and NotFoundComponent for route-level errors

### Route Structure

- **src/routes/__root.tsx**: Root layout with QueryClientProvider, meta tags, error boundaries
- **src/routes/index.tsx**: Main application page with all volleyball management UI
- **src/routeTree.gen.ts**: Auto-generated route tree (regenerated by TanStack Router plugin)

### Business Logic

**src/lib/volei.ts** contains core volleyball game logic:

- **Team Formation**: `pickTeam()` ensures gender balance (1 woman per 4-player team) by picking the first woman from queue, then completing with next 3 players in order
- **Scoring Rules**:
  - Base target: 12 points
  - Tiebreak rule: If 11-11, match goes to 14 points (TIE_POINT + 3)
  - `currentTarget()` calculates the current winning score based on game state
- **State Management**: localStorage persistence with "volei-galera-state-v2" key
- **Queue Management**: Maintains FIFO order for players waiting to play
- **Match Flow**: Losing team returns to queue; winner stays; next challenger is formed from queue

### UI Components

All UI components are in **src/components/ui/** and use:
- Radix UI primitives for accessible interactions
- Tailwind CSS for styling
- class-variance-authority (cva) for variant management
- Composition pattern with forwardRef

Path alias `@/*` maps to `src/*` (configured in tsconfig.json:24).

### Styling

- **src/styles.css**: Global styles and Tailwind CSS imports
- TailwindCSS v4 configuration via @tailwindcss/vite plugin
- Dark mode support via CSS variables and class-based theming

## Code Patterns

### State Persistence
The app uses localStorage for state persistence. All state changes trigger `saveState()` (src/routes/index.tsx:62), and state is loaded on mount with hydration flag to prevent SSR/client mismatch.

### Player Management
- Players have unique IDs generated via `uid()` (random 8-char alphanumeric)
- Players can be in three states: in queue, on court (teamA/teamB), or benched (not in queue, not on court)
- Removing a player from a team cancels the current match and returns other team members to queue

### Match Lifecycle
1. Players added to queue
2. "Montar times" picks 8 players (2 teams of 4, each with ≥1 woman)
3. Score tracked with +/- buttons or "Venceu" (won) button
4. Reaching target score auto-declares winner
5. Losing team → queue; winner stays; new challenger formed from queue
6. History stores last 30 matches (src/routes/index.tsx:218)

## Deployment

The app is configured for Cloudflare Workers:
